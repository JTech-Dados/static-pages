## Decisões

- **2026-10-14 — Site isolado do painel com CSP `sandbox`.** Uploads são servidos na mesma origem do `/admin` e o File Browser guarda o token no `localStorage`. Sem isolamento, um HTML enviado poderia roubar a sessão de quem o abrisse. Efeito colateral aceito: páginas do site não têm `localStorage`/cookies. Saída definitiva (futura): admin em subdomínio próprio.
- **2026-10-14 — File Browser roda como usuário `nginx` (su-exec).** Ele grava uploads com modo fixo 0640; rodando como root, os arquivos ficavam `root:root` e o NGINX respondia 403.
- **2026-10-15 — Proxy Caddy desativado.** A VPS já tem NGINX como proxy reverso; `proxy/` fica só como referência.
- **2026-10-15 — DESIGN.md (estilo Vercel) como contrato visual**, com logo próprio (não usar o logo da Vercel).
- **2026-10-21 — Time = pasta com `.time.json`; membro = usuário com escopo.** O File Browser v2 não tem grupos nem cota; o escopo por usuário é o único isolamento nativo.
- **2026-10-21 — Colunas "Time/Alterado por" só para admin.** Para o membro ler `.autoria`, seria preciso desligar "ocultar dotfiles", e aí ele poderia apagar o `.time.json` do time.
- **2026-10-21 — Auditoria protegida por `auth_request` na própria API.** `/admin/api/users` só devolve 200 para admin — vira o "porteiro" sem servidor extra.
- **2026-10-21 — Cota só alerta.** O File Browser não bloqueia upload por tamanho; bloquear exigiria um serviço no meio.

- **2026-10-21 — Repo público; commits com o e-mail noreply do GitHub.** Os commits saíam com o e-mail corporativo, que expunha o nome da empresa. O histórico foi reescrito (`git filter-branch`, os hashes mudaram) e o repo local usa `user.email = <id>+djorshuam@users.noreply.github.com`. Antes de commitar de outra máquina, configure o mesmo e-mail.

- **2026-10-15 — Binário do File Browser 2.32 fica em `/filebrowser`**, não em `/bin/filebrowser`.
- **2026-10-15 — SSL corporativo quebra `apk` via https.** Criado `APK_HTTP=true` (só local). Pacotes continuam com assinatura verificada.
- **2026-10-15 — Linux diferencia maiúsculas: `Index.html` dava 403.** A diretiva `index` aceita as variações comuns.
- **2026-10-21 — Hooks recebem `DESTINATION=/srv` em upload/save**, não vazio. Só usar `DESTINATION` em rename/copy.
- **2026-10-21 — `/api/raw` de `.json` volta como JSON (content-type)**, não texto — não dar `JSON.parse` em objeto.
- **2026-10-21 — Cache HTTP devolvia `.registro` antigo** depois de restaurar; a linha continuava na lista. Leitura com `cache: "no-store"`. Pego pelos testes E2E.
- **2026-10-21 — Escapes em heredoc + Python viraram quebras reais** (`\n`, `\t`) dentro de JS e shell, quebrando a sintaxe. Validar com `node --check` / `bash -n` depois de gerar código por script.
- **2026-10-21 — `sed` com `&` na substituição** insere o texto encontrado (embaralhou o título da home). Editar o arquivo direto.
- **2026-10-21 — Rate limit do login (5/min) derrubou o CI**, que roda rápido. Testes reaproveitam o token (`login_token`); só um login pela tela.
- **2026-10-21 — Locator do Playwright por texto pegava dois cards** (o select "Mover para…" de outro time continha o nome). Localizar pelo `h3`.
- **2026-10-21 — `display:inline-flex` do `.btn` vence o atributo `hidden`.** Regra global `[hidden]{display:none!important}`.
- **2026-10-22 — Variante de compose para GitOps (Portainer).** O Portainer (GitOps) não materializa bind mount de arquivo, não tem o `.env` (ignorado pelo git) e o "Re-pull image" falha (`pull access denied`) se o serviço tiver `image:` junto de `build:`. Por isso existe `docker-compose.portainer.yml`: variáveis por `environment:` com padrão, só `build:`, backup com imagem própria (`Dockerfile.backup`) e volume nomeado, rede fixa `static-pages-net` e sem porta no host. O `docker-compose.yml` original (env_file, bind mount, porta) continua sendo o padrão para VPS/Coolify.
- **2026-10-21 — Rede corporativa: Edge headless não captura `http://localhost`**, mas o Playwright com `channel="msedge"` funciona.

- **2026-10-21 — Publicação sob um prefixo (`SP_BASE`) sem o proxy remover o caminho.** O File Browser precisa de `baseURL` e gera links absolutos, então o prefixo tem de chegar até ele. Para não reescrever todas as locations, o NGINX do container remove o prefixo com `rewrite` antes de escolher a location e repassa a URI original ao File Browser (`$request_uri`). Alternativa descartada: o proxy fazer `rewrite` (quebraria assets e redirects do File Browser). Vazio = raiz, o padrão.
- **2026-10-21 — Entra ID no painel: ponte "troca de senha" em vez de `auth.method=proxy`.** O File Browser só tem um método de autenticação por vez; `proxy` desligaria o login do admin por senha (contingência). Então o sp-auth valida o ID token e, para membros cadastrados por e-mail, troca a senha por uma aleatória e a tela de login usa o formulário nativo. Vantagem: sessão, cookies e escopos do File Browser intactos e nada guardado em disco. Custo: a conta técnica `sp-svc` (admin) e o Node na imagem. Alternativas descartadas: oauth2-proxy (exige app registration Web com secret) e validar no NGINX com njs (sem onde guardar o estado dos pedidos).
- **2026-10-21 — Quem entra: e-mails cadastrados + pedido de acesso aprovado pelo admin.** Sem lista de grupos do AD. Pessoa sem cadastro faz login Microsoft, pede acesso e o admin escolhe o time na aba Pedidos da tela Acessos. Só o `admin` local (sem `@`) e o `sp-svc` ficam por senha.
- **2026-10-22 — Admin promovido ficava trancado para fora do Microsoft.** A decisão original era "admin só com senha"; quem promovia um membro quebrava o login dele. Agora contas de e-mail entram pela Microsoft, inclusive admin; só o `admin` local e `sp-svc` ficam por senha. A senha do admin por e-mail é trocada a cada login Microsoft (o `admin` local é a contingência).
- **2026-10-22 — Barra de espaço invisível.** O File Browser usa `vue-simple-progress` com estilo inline; 5 KB de 200 MB dá 0,003% de largura. CSS com `!important` e `min-width`.

Como este repo é um modelo público e há quem edite a home pelo painel, `HOME_FROM_SRV=true` mantém o comportamento antigo (semeia e serve do `/srv`). - **2026-10-22 — Todo envio acima de 1 MB dava 500 (achado ao testar os tokens de API).** O `auth_request /_cota` é uma subrequisição que herda o `Content-Length` do upload, e o `location = /_cota` não tinha `client_max_body_size`: valia o padrão de 1 MB, o sp-auth nunca era consultado, o `auth_request` recebia 413 e o NGINX respondia 500. Valia para **todas** as escritas pela API (membros e admin; as menores que 1 MB passavam, por isso os testes antigos não pegaram). Corrigido com `client_max_body_size 0` em `/_cota` e teste de regressão com envio de 3 MB. Reimplante o `pages` para valer na VM.

- **2026-10-23 — Entra por site reativado (saiu do backlog adiado).** Feedback de usuários: "centralizar pode não ser a solução, tem coisa que é informação restrita". A spec de 2026-10-22 assumia que um cookie assinado bastaria, o que **não vale** sob o CSP `sandbox` dos sites: a origem do documento é opaca, as requisições da própria página (assets e `fetch`) são cross-site e não levam cookie `SameSite=Lax`; cookie `SameSite=None` com CORS para `null` + credenciais abriria o conteúdo restrito a qualquer HTML sandboxed de outro time; tirar o sandbox expõe o token do painel. A abordagem é decidida no parecer do tech-lead (ver a spec). Enquanto não sai, o guia segue avisando que as páginas são públicas para quem alcança a URL.
- **2026-10-23 — Entra por site (v1) implementado; armadilhas do NGINX.** (1) O `auth_request` **não expande variável** na URI da subrequisição, e o `$sp_time` (um `map` sobre `$uri`) vale `_site_auth` dentro dela: o gate recebe o `$request_uri` em `X-Orig-Uri` (este sim é o da requisição original) e só aceita caminho limpo; caminhos com `..`, `//` ou `%` são negados, para nunca divergir da normalização do NGINX (`/outro/../time/` seria um desvio). (2) `proxy_pass` com parte de URI não vale em `location` regex nem nomeado; o gate usa `location = /_site_auth`. (3) Depois de um `rewrite`, as capturas do `location` se perdem. (4) `nginx -s reload` logo depois de copiar a configuração para o container pode correr contra o teste e deixar workers antigos: confira com `nginx -t` e rode de novo. (5) `/database/restritos` criado pelo entrypoint como root não era gravável pelo sp-auth: `chown nginx`. (6) O cache de 30 s de `fb.users()` negava quem acabou de entrar no time: a entrada (limitada por IP) relê antes de negar. (7) Marcador de time apagado fica órfão: reconciliado no boot. (8) Descartado: token na URL (vaza no `access.log` e no `visitas.log`, que vira `/_visitas.json`), cookie `SameSite=None` (bloqueado em navegadores com proteção de rastreamento) e origem separada (DNS/proxy). **O que não dá para garantir:** editores e admins leem pelo painel; quem tem acesso repassa o conteúdo; cópias em navegador/proxy de antes do toggle; o nome do time segue público; backups guardam o conteúdo.
- **2026-10-23 — "ver site" na lista de arquivos do painel.** Pedido: abrir a página publicada sem sair do painel para passar pela home. O `inject.js` põe um link "ver site ↗" ao lado do nome das pastas que são página e do `index.html` (que aponta para a pasta); membros montam o endereço com a pasta do time (`d.time` de `/entra/me`), admin já vê o caminho completo. A decisão de ser página vem da lista pública `/_pastas/<pasta>/` (tem `index.html`?), com cache de 30 s e uma requisição por pasta visível; time restrito responde 401 e também ganha o link. O link barra a propagação de clique e duplo clique (senão selecionaria ou abriria a linha). Pastas que começam com `_` ou `.` não ganham.
- **2026-10-22 — Painel preso ao tema claro.** O File Browser põe `html.dark` sozinho quando o sistema do usuário está em modo escuro; como o branding só cobre o claro, o painel ficava metade escuro (lista, breadcrumb e mensagens ilegíveis) para quem usa Windows/Edge escuros. O `inject.js` mantém `html.light` (MutationObserver) e o `custom.css` declara `color-scheme: light`. Armadilha: a regra `color-scheme` tem de vir **depois** do `@import` no `custom.css`; antes dele o `@import` é ignorado e o painel inteiro perde os tokens.
- **2026-10-22 — Lixeira para o editor, em lista por item.** A aba Lixeira era só de admin e a pasta `/_lixeira/<dia>/<lote>/...` crua confundia (pastas de data e lote, caminho inteiro). O sp-auth passou a expor a lixeira (`GET /lixeira`, `POST /lixeira/restaurar|apagar`) lendo o `.registro` e operando direto no `/srv`, porque o escopo do editor não alcança `/_lixeira`. Visibilidade: editor só vê o que saiu de `/<time>/`; leitor 403. Restaurar com nome ocupado cria `(restaurado)` em vez de sobrescrever. O registro é reescrito por tmp+rename; uma exclusão no mesmo instante pode perder uma linha (o item continua em disco até a limpeza de 30 dias). Prompt para o Claude na tela Tokens de API: só funciona com Claude Code/Desktop na rede; no chat da web o Claude roda fora dela.
- **2026-10-22 — Acesso restrito travava em URL com espaço ou acento.** O gate (`/site/auth`) negava todo caminho com `%`, então `Teste%20Cockpit/` nunca liberava e o login Microsoft "não entrava". Agora decodifica a URL como o NGINX e nega só as formas que podem divergir (`..`, `//`, `%2f`, UTF-8 inválido); e sem alvo restrito reconhecido responde 401, não 200.
- **2026-10-22 — Restrição por página (pasta do 1º nível).** Pedido do dono: restringir uma página, não o time todo. Página restrita tem lista própria e o time segue público; o cookie é por alvo com `Path` do time (o `Path` com nome codificado dependeria de como cada navegador escapa espaço e acento e repetiria o bug do login). Páginas mais fundas (`time/a/b`) herdam a restrição da pasta `a`. O nome da página continua visível na home (cadeado), como o do time.
- **2026-10-22 — Acento no nome de uma página quebrava o contador de visitas de todo o site.** O NGINX grava `$uri` com `\xC3\xBA` no log; o `sp-visitas` copiava isso para `_visitas.json`, que ficava inválido, e a home perdia todos os contadores. O `sp-visitas` troca `\xHH` por `%HH` e a home decodifica as chaves. De quebra, páginas com espaço passaram a mostrar visitas (a chave era comparada com a URL codificada).
- **2026-10-22 — "Alterado por" só existia para admin.** Membros têm `hideDotfiles` e não leem o `.autoria`; o painel agora pergunta ao sp-auth (`GET entra/autoria`), que lê o arquivo dentro do escopo do usuário, devolve nome curto (o e-mail vai no tooltip) e dá à pasta o último autor de dentro dela. A coluna Time continua só para admin.
- **2026-10-22 — Nome da conta anterior ficava na barra do painel.** O painel é uma SPA: sair e entrar com outra conta (ex.: do `admin` local para o login Microsoft) não recarrega a página e o `inject.js` guardava o `me` da primeira sessão, mostrando "admin" com o papel de Editor. - **2026-10-22 — "Peça ao time responsável" não dizia quem.** Quem restringe pode informar, na tela Acesso restrito, quem aprova pedidos de acesso (nome ou e-mail, até 120 caracteres). O texto só chega na resposta 403 do `POST /site/entrar`, isto é, a quem já entrou com uma conta Microsoft válida e foi negado; nada vai para a página pública nem para o `.time.json`. Sem contato, a mensagem cita o time. Um fluxo de "Pedir acesso" com aprovação na tela fica como ideia (TASKS).
- **2026-10-22 — "Remover" no diálogo de pessoas apagava a conta.** O File Browser só tem usuário com escopo, então tirar alguém do time sem apagar é "Mover para… > Sem time". O botão passou a se chamar "Excluir conta" e a confirmação explica isso.
- **2026-10-22 — Pedir acesso (sem e-mail).** O botão só aparece depois de um login Microsoft válido e negado (sem formulário anônimo, para não virar canal de spam); o ID token não é consumido, então o mesmo token serve para tentar entrar e para pedir. Quem decide vê no painel (não há SMTP no container), por isso o contador no menu. Recusa trava novo pedido por 24 h; aprovar acrescenta o e-mail à lista do alvo.
